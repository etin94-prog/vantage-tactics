# 세로 A / 가로 C UI 개선 · 2026-11-17

사용자 선택에 따라 UI만 개선했다. **배포하지 않았다.** 로컬 개발본에는 기존 측정 중 AI 변경이 있으므로 배포 시에는 인수인계 8절의 배포용 사본 절차를 따라야 한다.

> 위 내용은 최초 로컬 검토 시점의 기록이다. 이후 사용자의 “배포해줘” 요청으로 아래 배포 절차를 진행했다.

## 변경 내용

- 세로(960px 이하): 선택 유닛과 행동 안내 아래에 이동(또는 이동 취소), 주요 행동, 대기를 상시 노출한다. 주요 행동은 현재 선택한 사용 가능 행동, 그 외 사용 가능 행동 순으로 기존 버튼 상태에서 고른다. 더보기로 전체 6개 행동을 확인한다. 비활성 행동의 이유 안내를 유지한다.
- 가로(960px 이하): 오른쪽 238px 패널에 기존 행동 버튼, 공격·마법 예측, 접을 수 있는 유닛 상세를 모은다. 내용이 길면 패널 내부에서 스크롤한다. 확정·취소는 44px 이상이다.
- 기존 DOM 요소와 이벤트를 이동하므로 피해/반격/MP/이동 가능 여부를 별도로 계산하지 않는다. 화면 회전 및 데스크톱 복귀 때 원래 위치로 돌려놓는다.
- 예측이 패널에 있을 때 전장 위 예측 상자를 피하려는 카메라 이동을 생략한다. 전투 판정에는 영향이 없다.
- FPS는 설정을 명시적으로 켰을 때 표시한다. 기존 켜기 설정은 유지한다.
- 세로 상단의 중복 행동 문구를 숨기고 행동 안내를 하단에 배치했다. 새 애니메이션은 추가하지 않았다.

## 완료 조건과 검증

- `npm test`: 161/161 통과. 주요 행동 선택, 이동 취소 노출, 모두 비활성인 상태, 입력 상태 불변 검증을 추가했다.
- `npm run check`: 통과.
- `npm run lab:test`: 35/35 통과.
- `npm run build`: 통과.
- `npm run bench:render`: 변경 전 0.45ms/frame → 변경 후 0.49ms/frame. 같은 1024타일, 390×586 뷰포트, scale 0.85, 1114 calls/frame. 단일 측정의 작은 차이이며 실제 폰 FPS나 메모리 검증을 의미하지 않는다.
- Chrome 로컬 브라우저 오류 0. 390×844, 844×390 화면 직접 확인. 960×600 가로도 패널 폭 238px, 가로 넘침 없음. 1280×800에서는 원래 데스크톱 DOM 위치로 복귀함.
- 더보기 3→6개, 접기, 비활성 이유, 소환 패널 열기/닫기, 가로 유닛 상세 열기/닫기, 예측을 표시한 상태로 회전했을 때 단일 예측 요소가 복귀하는 것을 확인했다.
- 공격 예측은 테스트 브라우저 메모리에서만 적을 인접 타일로 옮겨 기존 `previewAttack` 경로로 확인했다. 피해 7 / 반격 2 / HP 10→3 및 10→8. 공격을 확정하지 않았다. 검증 후 정상 초기 장면으로 초기화했다.
- 전후 그림은 동일 초기 전장/턴/배율, `renderer.reduced=true`로 움직임을 제거한 장면이다. 레이아웃 변화로 실제 전장 높이·폭은 달라진다. 시간 기반 새 연출은 없으므로 새 타이밍 테스트는 해당 없음. 기존 연출 테스트는 모두 통과했다.
- 실제 휴대폰 터치, 주소창/안전영역, 장시간 플레이는 **미확인**. 이전 V0의 사용자 확인을 이번 UI 확인으로 간주하지 않는다.
