## 후속 수정 — 직전 보고서 미완료 항목

사용자가 직전 보고서의 미완료 항목 수정을 요청했다. V1의 실행 중 캐시 재생성 지연과 첫 진입 진동 오류를 수정했다. V2 및 배포는 진행하지 않았다. 아래 최초 보고서는 변경 이력으로 유지하며, 현재 결과는 이 절을 우선한다.

### 수정 내용

- `drawTerrain()`의 지도 전체 동기 재생성을 약 2ms 작업 예산의 여러 프레임으로 나눴다. 생성 중에는 현재 보이는 타일을 최신 지형 데이터로 직접 그린다. 밀물 전의 지도나 일부만 완성된 지도는 표시하지 않는다. 새 변경이 들어오면 진행 중 작업을 재시작한다.
- 완성된 지도는 기존처럼 한 장의 화면 밖 캔버스를 재사용한다. 임시 지도 캔버스를 추가하지 않았다. 팬·선택 변경은 재생성을 일으키지 않는다.
- 첫 전투의 지형·재질 준비는 `setBattle()` 단계로 분리했다. 이 동기 로딩 시간은 프레임 성능 수치에서 숨기지 않고 아래에 따로 기록한다.
- `GameHaptics.cancel()`은 사용자 활성화가 명시적으로 false인 경우 `vibrate(0)`을 호출하지 않는다. 사용자 입력 뒤 취소 동작과 공격 접촉 시점은 유지한다. 이번 요청에서 지목한 진동 오류 수정 범위로 `src/haptics.js`를 수정했다.
- 과거 `lab-build.js` 개별 백업 누락은 소급하여 없었던 것으로 처리하지 않는다. 이번 수정에서는 해당 파일과 모든 빌드 자동 생성 파일을 먼저 복사했다.

1. 64×64 고정 시드, 5색 팔레트, 디더링 기반 지형 질감을 생성한다. 물·석재의 패턴을 구분하고 원래 지형색을 유지한다.
2. 다른 지형과 접한 변 안쪽에 약 2.5px 혼합 띠를 넣는다. 물과 육지 경계에는 점선 거품을 그린다.
3. 높이 단면에 5px 간격 지층과 윗면 밝은 테를 넣는다. 높이 숫자와 이동/공격/선택 표시는 별도로 유지한다.
4. 정적인 지형을 한 장의 지도 캔버스로 저장한다. 재질·높이가 같은 지형 조각도 2MB LRU 캐시에 재사용한다. 지도는 원래 도트 밀도를 넘겨 확대 저장하지 않는다.
5. 지도 객체, 지형/좌표/높이 값, 배율, DPR 변경 시 지도 캐시를 재생성한다. 밀물의 제자리 지형 변경도 감지한다. 팬 이동, 시간 경과, 선택 변경은 재생성하지 않는다.
6. 게임 시각의 새벽·낮·저녁·밤 색을 연속 보간한다. 고정 밝기 전장은 그 밝기를 우선한다. 화면 가장자리 음영과 부드러운 발밑 그림자를 넣는다. HP와 주요 정보 오버레이는 색 보정 후 그린다.
7. 물 반짝임 및 낮 먼지/밤 반딧불 24개를 시간 기준으로 계산한다. `renderer.reduced`에서는 둘 다 완전히 생략하고 정적인 지형·빛·정보는 유지한다.

## 성능

`npm run bench:render`는 실제 GPU Canvas가 아닌 **가짜 컨텍스트의 JS/호출 수 벤치마크**다. 폰 성능으로 해석하면 안 된다.

| 항목 | 변경 전 | 최종 변경 후 |
|---|---:|---:|
| JS ms/프레임 | 0.39 | 0.32 |
| Canvas 호출/프레임 | 3,114 | 796 |

동일 조건: stageIndex 1, 1024타일, 390×586, 배율 0.85, 60프레임.

별도 데스크톱 Chrome 하네스: 배율 1.25, DPR 2, 각 180프레임의 `draw()` CPU 경과 시간. GPU 완료/폰 FPS 측정이 아니다. 수치는 시스템 부하 영향을 받는다.

| 장면/뷰포트 | 전 평균 ms | 후 평균 ms | 후 p95 ms | 캐시 재생성 ms |
|---|---:|---:|---:|---:|
| 고지대 390×844 | 0.457 | 0.444 | 0.90 | 8.1 |
| 고지대 844×390 | 0.486 | 0.474 | 0.80 | 8.6 |
| 물가 390×844 | 0.401 | 0.397 | 0.70 | 9.4 |
| 물가 844×390 | 0.546 | 0.463 | 0.80 | 9.3 |

**5절의 프레임당 4ms 조건은 재생성 프레임에서 미충족이다.** 정상 프레임과 따로 판단해야 한다. 재생성은 한 타일의 지형을 바꾸고 다음 `draw()`를 실행한 경과 시간이다. 첫 진입 시 모든 질감을 생성하는 비용, 대규모 밀물, 연속 확대 및 실제 폰의 장시간 성능은 추가 확인 대상이다. 단순 정상 프레임 평균만으로 완료라고 선언하지 않는다.

실측 신규 캐시 합계는 고지대 12,598,560바이트, 물가 12,642,696바이트다. 이론적 상한은 지도 42MB + 조각 2MB + 지형 질감 약 0.25MB로 48MB 이내다. 빛/접지 그림자는 CanvasGradient를 사용하며 별도 화면 밖 비트맵을 만들지 않는다. B1 캐시와 별도다.

- 고지대와 물가에서 같은 지도·카메라·배율·`draw(12000)`로 전후 비교했다. 기존 공격 하네스의 수동 시점 호출 방식을 따르는 V1 전용 하네스다.
- 390×844 세로와 844×390 가로에서 비교 캡처 및 실제 `play.html` 전장을 확인했다. 지형, 높이, HP, 이동 범위, 선택 표시를 읽을 수 있다.
- 네 조건 모두 reduced 상태의 `draw(12000)`와 `draw(16000)` 전체 캔버스 PNG가 같았다. 시간에 따른 새 움직임이 남지 않는다.
- 네 조건 모두 팬 캐시 재사용, 지형 변경 및 확대 시 재생성, 메모리 예산 검증을 통과했다.
- V1 하네스의 브라우저 오류는 0건이다. 마지막 실제 전장 실행도 새 오류 0건이다.
- **최초 새 브라우저 진입에서는 기존 `GameHaptics.cancel()`의 `navigator.vibrate(0)` 호출이 사용자 제스처 전이라 Chrome intervention 오류 1건이 기록됐다.** 새 렌더러 예외는 아니지만, 최초 진입까지 포함한 콘솔 오류 0 조건은 미충족으로 남긴다. 범위 밖 `src/haptics.js`는 수정하지 않았다. 최초 로그와 후속 정상 로그를 모두 보존했다.
- 모두 **데스크톱 Chrome 확인**이다. V0 사용자 폰 확인과 V1의 실제 폰 확인은 다르다. V1 실제 폰, 모바일 Safari, 30분 이상 플레이는 미확인이다.
